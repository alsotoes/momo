## 2026-08-18 - CRLF Injection in File Metadata (Server side)
**Vulnerability:** The server `getMetadata` function accepted file hash and raw filename strings containing Carriage Return and Line Feed (`\r\n`) characters without sanitization.
**Learning:** While downstream clients/transports like `MomoTCPCommunicator` were explicitly blocking CRLF in `SendMetadata`, the server-side receiver function lacked its own defense-in-depth sanitization, violating the "trust nothing" rule. Because metadata processing parses string fields, an attacker could bypass clients to send `\r\n` characters, potentially enabling HTTP Request Smuggling, Protocol Smuggling, or Log Forging in downstream dependencies or logs.
**Prevention:** Always perform strict validation for CRLF characters (`strings.ContainsAny(val, "\r\n")`) on all boundary inputs directly in the receiving handlers (e.g., `getMetadata`), even if client-side libraries supposedly block it.
