# No Blog Post Justification: steering-rule-93-duplicate-jules-prs

This ADR records a **workflow rule** — how to consolidate duplicate Jules
PRs/branches opened for the same task. It is a repository-management procedure,
not an engineering decision about how momo is built.

The engineering journal documents momo's **product engineering**. A post about
tidying our own PR tracker does not belong in it. The rule remains the source of
truth in `openspec/config.yaml` (Rule 93) and `docs/AI_FLYING_SOLO.md`.

No blog post is required per Rule 76: the journal is the engineering record for
the product. (Its narrative post `052-rule-93-duplicate-jules-prs` was removed
from the journal for this reason.)
